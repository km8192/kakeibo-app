# 家計簿アプリ 実装プロンプト

> 「家計簿アプリ_要件定義書.md」（Draft 1.2）をもとに作成した、実装用のプロンプトです。
> Claude Codeなど、コード生成を行うAIエージェントにそのまま渡して使うことを想定しています。

---

あなたは経験豊富なフルスタックエンジニア兼UIデザイナーです。以下の仕様に基づいて、個人用の家計簿アプリを実装してください。

## 1. プロジェクト概要

自分専用（個人利用のみ、家族共有や外部提供は対象外）に使う、シンプルで入力が速い家計簿アプリを作る。既存の家計簿アプリは多機能・自動連携が強みだが操作が複雑になりがちなので、このアプリでは機能を絞り、**「支出を思い立った瞬間に3秒で記録できること」を最優先の価値**とする。

## 2. 技術構成

- **バックエンド**：Google Apps Script（Webアプリとして公開。`doGet`/`doPost` で JSON API を提供する）
- **データストア**：Googleスプレッドシート（1ファイル・7シート構成。詳細は「5. データ設計」を参照）
- **フロントエンド**：素のHTML/CSS/JavaScriptによるPWA（単一ページ内で画面をJSで切り替えるSPA構成。フレームワークは不要）
- **対応環境**：スマホブラウザ（iOS Safari／Android Chrome）を主対象、PCブラウザでも閲覧可能
- **ホーム画面追加**：`manifest.json` を用意し、スマホのホーム画面に追加してアプリのように起動できるようにする
- **オフライン対応・通知機能は今回のスコープ外**（将来検討事項。実装しなくてよい）

## 3. 最優先で守るべき設計原則

1. **入力の速さを最優先する**：入力画面を開いたら即座に入力できる状態にし、他画面への遷移をはさまない
2. **確認画面を挟まない**：カテゴリをタップした時点で入力を確定・保存する（「本当に保存しますか？」等の確認ステップは作らない）。直前の記録は一覧からワンタップで取り消せるようにする
3. **入力画面の項目は上から順に以下の並びとする**：
   `誰が`（チップ） → `支払い方法`（チップ） → `支出／収入`トグル → `金額`（テンキー） → `カテゴリ`（アイコン付きボタン）
4. **「誰が」「支払い方法」は入力画面から＋ボタンでその場で追加登録できる**（名前を入力するだけのシンプルな追加）
5. **カテゴリの追加・編集・削除は設定画面からのみ行う**（入力画面からは追加できない）。カテゴリには名称・アイコン・予算上限など編集項目が多く、入力画面に持ち込むと入力の速さを損なうため、あえて設定画面に集約する
6. **視認性重視の配色**：支出＝暖色系（赤系）、収入＝寒色系（緑系）など直感的な色分けにする
7. 応答速度：入力操作から保存完了まで体感1秒以内を目指す
8. **過去の平均額を参考表示する**：入力画面のカテゴリボタン下、および固定費の金額編集欄には、「誰が」×カテゴリ（固定費の場合は紐づけたカテゴリ）の過去の取引データから算出した平均額を薄く表示する。これは入力の参考値であり、自動入力や保存はしない
9. **月の区切りは締め日設定に従う**：`設定` シートに保存された締め日をもとに会計月（例：25日締め→前月26日〜当月25日）を算出し、サマリー表示・固定費の自動更新対象・月送り・予算集計など、月を単位とするすべての処理で共通のロジックを使う（締め日が空欄の場合は通常の暦月）

## 4. 画面仕様

アプリは以下4画面で構成する。画面遷移は基本的にこの1〜4の間を行き来する形でよい。

### 4.1 入力画面（ホーム／起動時の初期画面）
- 最上部：「今月の収支」表示エリア。**タップするたびに「残高」（総収入－総支出）と「使える残高」（総収入から、登録済みの固定費の合計を差し引いた金額）をラベルごと切り替え表示する**
- その下：「今月の予算（ざっくり）」表示エリア
  - カテゴリ別の積み上げではなく、月ごとに1つだけ手入力する予算（編集アイコンから金額を変更）
  - 対象は固定費を除いた変動費のみ：総支出から、`固定費` シートの「紐づけるカテゴリ」×「誰の」に一致する支出を除いた金額を使用額とする
  - 使用額・使用率（％）・残り金額（または超過額）をバーで表示する
  - **バーをタップすると、月を週ごとに分けた内訳をオーバーレイ表示する**（各週がその月に含まれる日数の割合で予算を按分し、週ごとの目安額と実際の使用率を表示。週は日曜始まりの暦週）
- その下：「誰が」チップ（登録済みメンバーを横並び表示、＋で追加、編集モードで削除・並び替え）
- その下：「支払い方法」チップ（同様の操作性）
- その下：支出／収入の切り替えトグル（ワンタップ）
- その下：金額表示（大きく表示）＋テンキー（0-9, 00, ⌫）。画面下部寄りに固定し、片手操作を想定する
- その下：カテゴリボタン一覧（アイコン＋ラベル、支出／収入トグルに応じて表示するカテゴリを切り替え）。**カテゴリをタップした時点で入力を確定・保存する**。各カテゴリボタンの下には、選択中の「誰が」×そのカテゴリの過去の平均額を薄く表示する（参考値。保存はしない）
- 保存後、直前の記録を数件（3件程度）簡易表示し、直前の1件には取り消しボタンを添える
- 金額が0のままカテゴリをタップした場合は「金額を入力してください」等のインラインエラーを表示し、保存しない
- **支出の保存時、`固定費` シートに「紐づけるカテゴリ」と「誰が」が一致し、かつ「自動更新」がONの行があれば、その行の金額を今回の取引金額で自動的に上書きする（後述 6. API仕様を参照）**
- 「今月」の範囲は、`設定` シートの締め日設定に従う会計月を使用する（後述）

### 4.2 履歴・一覧画面
- 月送り（◀▶）で表示月を切り替える。ここでの「月」は締め日設定に従う会計月とする
- 月次サマリー（収入・支出・差引）を表示
- カテゴリ・誰が・支払い方法のプルダウンによる絞り込み、メモ／金額によるキーワード検索
- 日付ごとにグループ化した一覧（各日の差引小計も表示）
- **各記録をタップすると編集画面（日付・誰が・支払い方法・カテゴリ・金額・メモ・種別を編集可能）を開き、保存または削除できる**

### 4.3 集計・グラフ画面
- 月送り（◀▶）。ここでの「月」も締め日設定に従う会計月とする
- 収入・支出・差引のサマリーと、それぞれの前月比（％）。支出は増加時に警告色、減少時に好調色など、家計にとっての良し悪しが直感的に分かる色分けにする
- 「カテゴリ別／メンバー別／支払い方法別」をタブで切り替えられる円グラフ（内訳の金額・割合を凡例表示）
- 日別支出の推移を示す棒グラフ（当月の日ごとの支出合計）

### 4.4 設定画面（ハブ形式）
- メニュー一覧から以下5つへ遷移する
  - **カテゴリ・予算設定**：支出／収入別に一覧表示。タップすると、名称・種別・アイコン・予算上限（月・任意）をまとめて編集。追加・削除も可能
  - **固定費設定**：名称・誰の・支払い方法・紐づけるカテゴリ・自動更新（ON/OFF）を登録。一覧は**メンバーごとに列を分けて横並び表示**し、各列に項目名・金額を縦に並べ、列ごとの小計と全体合計を表示する。支払い方法（すべて／現金／クレジット等）で一覧をフィルタリングでき、フィルタに応じて小計・合計も再計算される。金額の編集時は、紐づけたカテゴリ・誰がの過去の平均額を金額欄の下とプレースホルダーに薄く表示する
  - **メンバー設定**：一覧表示、▲▼で並び替え、×で削除、下部の入力欄から追加
  - **支払い方法設定**：メンバー設定と同様の操作性
  - **締め日設定**：1〜31の数値または「月末締め」を1つ選択する。この値が、上記すべての「月」の判定に使われる

## 5. データ設計（Googleスプレッドシート）

Googleスプレッドシート1ファイルに、以下7シートを作成する。各シートの1行目はヘッダー行、2行目以降が実データ。

### `取引` シート
| 列 | 項目 | 型 | 備考 |
|---|---|---|---|
| A | ID | 文字列 | 一意識別子（`Utilities.getUuid()`等で発行） |
| B | 日付 | 日付 | |
| C | 種別 | 文字列 | `支出` または `収入` |
| D | 誰が | 文字列 | メンバーシートの「メンバー名」と一致 |
| E | 支払い方法 | 文字列 | 支払い方法シートの「支払い方法名」と一致 |
| F | カテゴリ | 文字列 | カテゴリシートの「カテゴリ名」と一致 |
| G | 金額 | 数値 | 円単位の整数 |
| H | メモ | 文字列 | 任意 |
| I | 登録日時 | 日時 | サーバー側（Apps Script）で自動記録 |

### `カテゴリ` シート
| 列 | 項目 | 型 | 備考 |
|---|---|---|---|
| A | ID | 文字列 | 一意識別子 |
| B | カテゴリ名 | 文字列 | |
| C | 種別 | 文字列 | `支出` または `収入` |
| D | アイコン | 文字列 | Tabler outlineアイコン名（例：`ti-home`） |
| E | 表示順 | 数値 | |
| F | 予算上限（月） | 数値 | 任意。0または空欄は「設定なし」 |

### `メンバー` シート
| 列 | 項目 | 型 |
|---|---|---|
| A | ID | 文字列 |
| B | メンバー名 | 文字列 |
| C | 表示順 | 数値 |

### `支払い方法` シート
| 列 | 項目 | 型 |
|---|---|---|
| A | ID | 文字列 |
| B | 支払い方法名 | 文字列 |
| C | 表示順 | 数値 |

### `固定費` シート
| 列 | 項目 | 型 | 備考 |
|---|---|---|---|
| A | ID | 文字列 | 一意識別子 |
| B | 名称 | 文字列 | 例：家賃、電気代、携帯代 |
| C | 誰の | 文字列 | メンバーシートの「メンバー名」と一致 |
| D | 支払い方法 | 文字列 | 支払い方法シートの「支払い方法名」と一致 |
| E | 紐づけるカテゴリ | 文字列 | カテゴリシートの「カテゴリ名」と一致。自動更新・平均額ヒント・今月の予算の変動費判定に使用 |
| F | 金額（月） | 数値 | 自動更新ONの場合、該当する取引が記録されるたびにApps Script側で上書きする |
| G | 自動更新 | 真偽値 | `TRUE`/`FALSE` |
| H | 表示順 | 数値 | 一覧内での並び順 |

### 共通ルール
- IDは行番号に依存しない固有の文字列で発行する（行の削除・並び替えに影響されないようにする）
- マスタ（カテゴリ・メンバー・支払い方法）の項目を削除・改名しても、`取引` シート側の過去データはそのまま残す（自動追従はさせない）
- **固定費の自動更新**：`addTransaction` 実行時、種別が「支出」の場合は `固定費` シートを参照し、「紐づけるカテゴリ」と「誰の」が今回の取引と一致し、かつ「自動更新」がTRUEの行があれば、その行の「金額（月）」を今回の取引金額で上書きする
- **過去の平均額の算出**：平均額専用の列・シートは持たず、`取引` シートのデータから都度、「誰が×カテゴリ」（または固定費の「誰の」×「紐づけるカテゴリ」）で絞り込んで平均を計算し、フロントエンドに返す
- **会計月（締め日）の算出**：`設定` シートの締め日Dを取得し、対象日が「前月D+1日〜当月D日」のどちらに属するかを判定して会計月を決定する共通関数（例：`getFiscalMonth(date)`）をApps Script側に用意する。締め日が空欄または31の場合は通常の暦月として扱う。D日がその月に存在しない場合はその月の末日を締め日とみなす。この関数は、取引の月別取得・固定費の自動更新対象月の判定・月次予算の集計・週別内訳の按分など、月を単位とするすべての処理から共通で呼び出す

### `月次予算` シート
| 列 | 項目 | 型 | 備考 |
|---|---|---|---|
| A | 年月 | 文字列 | 会計月を表すキー（例：`2026-09`） |
| B | 金額 | 数値 | その会計月の「ざっくり予算」（固定費を除いた変動費が対象） |

- 1会計月につき1行。同じ月内で金額を編集した場合は新規行を追加せず、既存行を上書きする

### `設定` シート
| 列 | 項目 | 型 | 備考 |
|---|---|---|---|
| A | 締め日 | 数値または空欄 | 1〜31の数値、または空欄（空欄・31は月末締め＝通常の暦月） |

- アプリ全体で1行のみ使用する

### 初期データ（シード）
アプリの初回セットアップ時、以下を初期データとして投入する。

- **カテゴリ（支出）**：家賃（`ti-home`、予算80,000円）、食費（`ti-tools-kitchen-2`、予算30,000円）、交通費（`ti-bus`、予算5,000円）、日用品（`ti-shopping-cart`、予算5,000円）、交際費（`ti-users`、予算5,000円）、電気代（`ti-bolt`、予算なし）、その他（`ti-dots`、予算5,000円）
- **カテゴリ（収入）**：給与（`ti-cash`）、その他（`ti-dots`）
- **メンバー**：パパ、ママ
- **支払い方法**：現金、クレジット
- **固定費**：初期データなし（ユーザーが設定画面から登録する）
- **月次予算**：初期データなし（ユーザーが入力画面から設定した月から記録される）
- **設定**：締め日は空欄（＝月末締め・通常の暦月）で初期化

## 6. API仕様（想定）

Apps ScriptのWebアプリは `doGet(e)` / `doPost(e)` のみで公開されるため、`e.parameter.action`（GETの場合）または POSTボディのJSON内の `action` フィールドでルーティングする方式とする。想定するアクション例：

- `getTransactions`（月指定で取引一覧を取得）
- `addTransaction` / `updateTransaction` / `deleteTransaction`（`addTransaction` は保存時に固定費の自動更新チェックも行う。前述「共通ルール」参照）
- `getMasters`（カテゴリ・メンバー・支払い方法をまとめて取得）
- `addCategory` / `updateCategory` / `deleteCategory`
- `addMember` / `updateMember` / `deleteMember` / `reorderMembers`
- `addPaymentMethod` / `updatePaymentMethod` / `deletePaymentMethod` / `reorderPaymentMethods`
- `getFixedCosts` / `addFixedCost` / `updateFixedCost` / `deleteFixedCost` / `reorderFixedCosts`
- `getAverageAmount`（誰が・カテゴリを指定して、過去の取引からの平均額を返す。入力画面のカテゴリボタンおよび固定費の金額編集欄のヒント表示に使用）
- `getMonthlyBudget` / `setMonthlyBudget`（会計月を指定して「今月の予算（ざっくり）」を取得・保存する）
- `getWeeklyBreakdown`（会計月を指定して、週ごとの目安額・実績・使用率の内訳を返す。予算バーのタップ時に呼び出す）
- `getSettings` / `updateSettings`（締め日など、`設定` シートの内容を取得・更新する）

レスポンスはJSON形式で返し、フロントエンドは `fetch` で呼び出す。

- `index.html` … PWA本体（HTML/CSS/JSを1ファイルにまとめてよい。4画面をJSで切り替えるSPA構成）

- `README.md` … デプロイ手順（スプレッドシートの用意、Apps Scriptのデプロイ、`index.html`側のAPI URL設定方法など）

## 8. スコープ外（今回は実装しない）

- オフライン時の入力対応（一時保存→オンライン復帰時の同期）
- 予算超過等の通知機能
- 家族共有・複数アカウントでの利用
- CSV等でのエクスポート機能
